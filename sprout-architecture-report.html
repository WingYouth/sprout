1. Runtime 调用了哪些东西

统一入口是 src/Sprout/runtime/factory.py:create_runtime。CLI、Web API、MCP 和 Gateway 都应通过这个 factory 获得同一套 Runtime 装配方式。

核心运行层安全与模型数据与能力实线：主要调用　虚线：事件/辅助关系
Runtime 主要子系统SessionManagerContextBuilderWorkspaceServiceTask/ChangeProposalApplyBrokerGit/File/Process/Network/Database Broker
Runtime 的外部接入

CLI chat、Web chat/project/approval、RPC、Feishu、WeChat、MCP 均把请求转成 Runtime 操作；transport 不应自己复制业务编排。

当前边界

Runtime 本身不直接依赖具体 transport，也不直接决定模型供应商；factory 负责 storage、model、security、tools、skills、orchestrator 的装配。

3. 审计被哪些部分调用

审计分成两条互补路径：安全决策使用哈希链 JSONL，运行观察使用 EventBus/ObservationStore。两者不是同一个文件，也不应混为“日志”。

SecurityAuditLog

实现：src/Sprout/security/audit.py

文件：~/.sprout/data/audit/security.jsonl

记录 policy decision、approval decision、命令 allowlist、网络拦截、授权异常及审计写入失败。每条记录带 prev_hash 和 hash。

Audit 调用入口

SecurityLayer 注入审计对象；PolicyEngine / layered policy、ApprovalManager、CommandBroker、NetworkGuard、SecretBroker、Process/Git/Database/File 执行边界会触发安全决策记录。

Runtime / Agent 观察

Runtime、AgentLoop、ToolExecutor、事件总线发布生命周期和工具事件；ObservationRecorder 订阅并写入 observations lane。模型调用与工具用量另写 usage store。

CLI / Web 读取与操作

CLI：sprout audit verify、sprout audit tail、approval 命令；Web：approval 列表/决策、runtime 状态和事件相关接口。它们通过 Runtime 或存储契约访问，不直接改 hash 链。

4. CLI 结构

入口：src/Sprout/cli/app.py。无子命令进入 chat；其余命令按 Typer 子应用注册。

默认交互

sprout → chat → RuntimeGateway → Runtime

Slash 层包含 /skill、/db、/project、/audit、/approval、/model、/language 等。

运行与服务

chat、serve、info、stop

Web 和 RPC 也复用 Runtime factory。

数据与审计

db、storage、session、memory、audit、approvals

能力与编排

skills、project、evolution、orchestrator、gateway、remote、mcp、model

CLI 的配置来源是 TOML / 环境变量；Runtime 启动前由 factory 创建 storage、模型、SecurityLayer、工具注册表、Skill 注册表和本地/Temporal 编排后端。

5. 落库、封箱与当前数据库使用关系

“封箱”可理解为数据边界：业务模块通过 storage contract 和 StorageBundle 访问数据库，具体 DSN 决定 SQLite、Redis、Milvus、Neo4j、JSONL 或 BlobStore 后端；业务代码不应绕过 contract 直连数据库。

数据库封箱边界

Assembly

create_storage(settings.storage) 创建 StorageBundle，统一暴露 operational、knowledge、skills、sessions、metadata、observations、vectors、cache、blobs、memory、context、usage 等契约。

Authority

SQLite、JSONL、BlobStore 是可恢复的权威/证据层；Redis、Milvus、Neo4j 是可重建的派生层。项目数据库位于 projects/{project_id}/，不能由 Sprout runtime 状态冒充。

Fan-out

SixLaneFanout 把 session/turn/fact/context 写入主存储后镜像到 FTS、Redis、Milvus、Neo4j；镜像失败应记录 lane error，不改变主权威数据。
