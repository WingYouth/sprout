设计原则：所有库都按物理边界拆成两套，但 schema 不相同。sprout_* 记录这个 Sprout 项目自己如何运行；projects/{project_id}/project_* 记录用户项目本体，包括后端、前端、agent、skill、项目结构、数据库关系、数据库拆解和版本进化。

字段模板视图：两套 schema，两种职责

这张图只表达字段模板，不表达运行流。左边是 Sprout 自身运行 schema；右边是用户项目本体 schema。两套 schema 不共享表结构，只通过 bridge id、Neo4j 边和证据 URI 关联。

Sprout 自身运行 schema
sprout_core.Task(id, title, instruction, status, priority, actor_json, target_ref_type, target_ref_id, context_snapshot_id, created_at, completed_at)
sprout_core.ExecutionRun(id, task_id, agent_name, model, sandbox_id, status, result_json, error, started_at, ended_at)
sprout_core.ExecutionStep(id, run_id, seq, kind, status, input_json, output_json, tool_calls_json, duration_ms)
sprout_conversation.Session(id, user_id, channel, title, status, metadata_json, created_at, updated_at)
sprout_conversation.Message(id, session_id, seq, role, content, content_blob_uri, token_estimate, metadata_json)
sprout_knowledge.KnowledgeItem(id, kind, title, content, evidence_json, confidence, version, status)
sprout_audit.Approval(id, task_id, tool, status, resource_scope, action_hash, expires_at, used_at)
sprout_usage.ModelCall(id, provider, model, task_id, run_id, input_tokens, output_tokens, latency_ms, cost_usd)
sprout_trajectory / sprout_blobs / sprout_redis / sprout_milvus are evidence or derived indexes

Sprout Task target_ref_id points to Project / Component / File / Table / Interface records
Sprout ChangeSet maps to project_evolution.EvolutionChangeSet

DataAccessPoint links DatabaseTable usage back to FileNode and SymbolNode
Neo4j materializes cross-schema paths; SQLite remains authoritative
Blob URI stores large schemas, diffs, logs and evidence without duplicating table rows
